# Secrets with SOPS + age (KSOPS in Argo CD)

Kubernetes Secrets are never committed in plaintext. Instead:

- `secret.template.yaml` files are committed and contain only `${VAR}`
  placeholders (documentation of the required keys).
- `secret.enc.yaml` files are committed **encrypted** with
  [SOPS](https://github.com/getsops/sops) using an
  [age](https://github.com/FiloSottile/age) recipient.
- Argo CD's repo-server decrypts them at render time through the
  [KSOPS](https://github.com/viaduct-ai/kustomize-sops) kustomize plugin,
  using the age private key mounted from the `sops-age` Secret.

Plaintext values live only in `deploy/k8s/.env.prod` (gitignored) and in the
age private key `deploy/k8s/.age/keys.txt` (gitignored).

This is safe for a public repository: without the age private key the
encrypted files are unreadable.

## Layout

```text
.sops.yaml                       # creation rules + age recipient
deploy/k8s/.env.prod.example     # list of values to provide
deploy/k8s/.env.prod             # gitignored, plaintext values
deploy/k8s/.age/keys.txt         # gitignored, age private key
deploy/scripts/secrets/
  init-age-key.sh                # generate key, write .sops.yaml, create sops-age
  seal-prod-secrets.sh           # render templates + encrypt to secret.enc.yaml
  install-argo-ksops.sh          # patch Argo CD repo-server for KSOPS
deploy/k8s/bootstrap/argocd/ksops/
  argocd-cm-patch.yaml           # --enable-alpha-plugins --enable-exec
  argocd-repo-server-patch.yaml  # KSOPS init container + age key mount

deploy/k8s/apps/<app>/overlays/prod/
  secret.template.yaml           # committed, ${VAR} placeholders
  secret-generator.yaml          # commits the ksops generator
  secret.enc.yaml                # committed, encrypted
```

## One-time setup

Requirements: `age-keygen`, `sops`, `envsubst` (`gettext-base`), and `kubectl`.

```bash
# 1. Generate the age key, write .sops.yaml, and create the sops-age Secret.
./deploy/scripts/secrets/init-age-key.sh

# 2. Provide the real values.
cp deploy/k8s/.env.prod.example deploy/k8s/.env.prod
$EDITOR deploy/k8s/.env.prod

# 3. Render and encrypt every secret.
./deploy/scripts/secrets/seal-prod-secrets.sh

# 4. Commit the generated secret.enc.yaml files.
git add 'deploy/k8s/**/secret.enc.yaml' .sops.yaml
git commit -m "chore(secrets): seal prod secrets with sops"
```

`init-age-key.sh` creates the `sops-age` Secret when a cluster is reachable.
If you ran it before installing Argo CD, create it after installing Argo CD:

```bash
kubectl create secret generic sops-age -n argocd \
  --from-file=keys.txt=deploy/k8s/.age/keys.txt
```

Then patch Argo CD so the repo-server can use KSOPS:

```bash
./deploy/scripts/secrets/install-argo-ksops.sh
```

## Day-to-day

**Change a value / rotate a secret**

1. Update `deploy/k8s/.env.prod`.
2. Run `./deploy/scripts/secrets/seal-prod-secrets.sh`.
3. Commit the changed `secret.enc.yaml` file(s). Argo CD picks it up.

**Add a new key to an existing secret**

1. Add the key with a `${VAR}` value to the relevant `secret.template.yaml`.
2. Add `VAR=` to `deploy/k8s/.env.prod` (and `.env.prod.example`).
3. Re-run the seal script and commit.

**Add a whole new service secret**

1. Create `secret.template.yaml` and `secret-generator.yaml` (copy an existing
   one) in the overlay.
2. Add `generators: [secret-generator.yaml]` to that overlay's
   `kustomization.yaml` (and drop `secret.yaml` from `resources` if present).
3. Add the new variables to `.env.prod`, run the seal script, commit.

## Verify

```bash
# Point sops at the non-default age key location:
export SOPS_AGE_KEY_FILE="$PWD/deploy/k8s/.age/keys.txt"

# Decrypt a file locally:
sops --decrypt deploy/k8s/apps/api/overlays/prod/secret.enc.yaml

# Render the overlay (needs kustomize + ksops on PATH):
kustomize build --enable-alpha-plugins --enable-exec \
  deploy/k8s/apps/api/overlays/prod
```

## Fresh clone / CI

Each prod overlay references `secret.enc.yaml` through its
`secret-generator.yaml`. Those files are generated by the seal script and are
committed once sealed. On a fresh clone where they are missing, `kustomize
build` of a prod overlay will fail until you either:

- run `init-age-key.sh` + `seal-prod-secrets.sh` with the values, or
- check out the already-committed `secret.enc.yaml` files (they only need the
  age key to decrypt, not to exist in git history).

`deploy/k8s/.env.prod` and `deploy/k8s/.age/` are gitignored and must never be
committed.

## Local environment (`deploy/k8s/local`)

The local k3d environment uses the **same** SOPS + age + KSOPS mechanism as prod,
but with its own values and its own encrypted files:

| | Prod | Local |
|---|---|---|
| Values file | `deploy/k8s/.env.prod` (gitignored) | `deploy/k8s/.env.local` (gitignored) |
| Templates | `**/overlays/prod/secret.template.yaml`, `infra/minio/` | `**/overlays/local/secret.template.yaml`, `local/minio/` |
| Seal script | `seal-prod-secrets.sh` | `seal-local-secrets.sh` |

The two seal scripts are mutually exclusive by design — each excludes the other
environment's paths — so sealing one can never overwrite the other's
`secret.enc.yaml`.

**Guides**

1. Copy `deploy/k8s/.env.local.example` → `deploy/k8s/.env.local` and fill it in.
2. `./deploy/scripts/secrets/init-age-key.sh` (once per machine).
3. `./deploy/scripts/secrets/seal-local-secrets.sh`.
4. Commit the generated local `secret.enc.yaml` files.
5. Patch the local Argo CD repo-server with KSOPS:
   `./deploy/scripts/secrets/install-argo-ksops.sh`.

The `*.enc.yaml` local files are safe to commit (encrypted). `deploy/k8s/.env.local`
and `deploy/k8s/.age/` are gitignored and must never be committed.

## Security notes

- **Back up `deploy/k8s/.age/keys.txt` somewhere safe and offline.** Losing it
  means every committed `secret.enc.yaml` becomes unrecoverable.
- Never commit `.env.prod`, `.env.local`, or the age key; `.gitignore` already
  excludes them.
- To rotate the age key: generate a new one, add the new recipient to
  `.sops.yaml`, run `sops updatekeys` on each encrypted file, replace the
  `sops-age` cluster Secret, and re-seal.
- Encrypted files are integrity-protected: editing them by hand makes Argo CD
  fail to decrypt. Always go through the seal script.
